## 1. 요약 결론

| 요구 기능 | 지원 여부 | 비고 |

| 미국주식 시세·차트 | ✅ 지원 | NAS/NYS/AMX, 통합차트 1회 최대 5,000건, 수정주가 옵션 |
| 국내주식 주문·정정·취소 | ✅ 지원 | 지정가/시장가/최유리/최우선/중간가, KRX·NXT·SOR, 시간외종가, 소수점 |

| 환율 조회 | ✅ 지원 | IVA60190 환율종합, 주문가능금액 조회 시 적용환율 |
| **모의투자(페이퍼 트레이딩) API 환경** | ❌ **미제공** | 공식 접속 정보에 운영 환경 URL만 있음 |
| **실시간 시세 푸시(WebSocket)** | ❌ **문서상 없음** | 모든 API가 REST(POST). 폴링 방식만 가능 |
| **환전 API** | ❌ **없음** | 환율 조회만 가능. 환전은 HTS/MTS에서 수동 |
| 재무제표·뉴스 | ⚠️ 제한 | 기업개요(IVM10050)만 있음. 재무·뉴스는 외부 데이터 필요 |
| 호출 제한(rate limit) 수치 | ⚠️ 비공개 | "호출 제한 정책"이 있다고만 명시, 수치는 없음 |
| 오류 코드 목록 | ⚠️ 비어 있음 | 오류코드 페이지 0건. 응답 `o_clsf`/`o_msg`로 판별해야 함 |
| 미국 LOC/MOC 등 장마감 주문 | ❌ 없음 | 일 1회 리밸런싱 시 주문 시점 설계에 영향 |

**결론: 시세 조회·주문·잔고 등 핵심 기능은 KB증권 Open API로 국내·미국 모두 가능합니다.** 다만 아래 3가지 제약이 계획에 직접 영향을 줍니다.

1. **모의투자 API가 없습니다** → 모의투자는 "KB 실시세 + 자체 체결 시뮬레이터"로 구현해야 합니다.
2. **실시간 푸시가 없습니다** → 장중 매매는 REST 폴링으로 구현해야 하고, 호출 제한 때문에 종목 수에 한계가 있습니다.
3. **환전 API가 없고 통합증거금(글로벌원마켓) 구조가 있습니다** → KRW/USD를 분리 관리하려면 시스템 쪽 장치가 필요합니다.

## 2. 공통 사항 (인증·호출 규격)

- 운영 URL: `https://developer.kbsec.com:32484`. 개발가이드에는 "운영 환경 및 테스트 환경은 아래와 같이 구분"이라고 쓰여 있지만, **표에는 운영 환경만 있습니다.**
- 인증: OAuth2 Client Credentials (`POST /oauth2/token`, appKey/appSecret) → Bearer 토큰, **유효기간 86,400초(24시간)**, 폐기 API(`/oauth2/revoke`)가 있습니다.
- 요청 형식: 모든 API가 `POST` + JSON이고, `dataHeader`에 **`ipAddr`, `macAddr`**를 넣어야 합니다(가이드 예시 기준, "최종 확정 예정"이라고 표기).
- 토큰 발급 시 검증 항목: appKey 유효 여부, API 사용 신청 여부, **API 권한, 계좌 권한, 호출 제한 정책** 등.
- 주문 API 입력에 **계좌번호 필드가 없습니다** → 앱키 ↔ 계좌가 묶여 있는 구조로 보입니다(계좌 권한). 앱키 하나로 계좌를 여러 개 쓸 수 있는지는 **확인이 필요합니다.**
- 응답 필드는 모두 문자열(String)이고 가격은 `P4`(소수 4자리), 일부 금액은 "*100 보정" 같은 스케일 규칙이 있습니다 → 파싱 계층이 꼭 필요합니다.
- 오류 처리: HTTP 200이어도 업무 오류일 수 있습니다. 가이드에 나온 오류 유형은 권한 없음, 계좌 권한 없음, 호출 제한 초과, 필수값 누락, 주문 불가입니다.
- 서비스 상태: 개인 고객 대상 **오픈베타**입니다. 명세의 작성일·버전이 계속 바뀔 수 있으니 주기적으로 명세를 다시 받아 비교해야 합니다.

## 4. 제약 사항과 대안 (증권사는 변경하지 않음)

### 4.1 모의투자 API 미제공
| 대안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 자체 페이퍼 브로커 (추천)** | KB 조회 API로 실제 시세를 받고, 체결은 시스템 내부 시뮬레이터가 처리(수수료·세금·슬리피지·호가단위·장시간 반영) | 실계좌 주문 API를 호출하지 않아 안전, 완전 자동화 가능, 백테스트와 같은 엔진 사용 | 실제 체결(부분체결·대기열·거부)과 차이가 생김 |
| B. KB 포털 "모의거래 체험" | 웹 화면에서 가상 계좌로 주문 체험 | 공식 제공 | 사람이 직접 "체결처리"를 눌러야 함, API 연동이 아님 → 자동화 불가 |
| C. KB 테스트 환경 출시 대기 | 가이드에 테스트 환경 언급만 있음 | 출시되면 가장 실제와 가까움 | 출시 시기 미정 → 일정 리스크 |
| (참고) 타 증권사 모의투자 | 다른 증권사 API 이용 | 실제 증권사 모의서버 사용 | **요구사항에 따라 선택하지 않음.** 주문 규격·코드 체계가 달라 KB 실거래 전환 시 재개발 필요 |

→ 계획서에는 **A안을 기본으로 하고, C안이 나오면 어댑터만 추가**하는 구조로 반영했습니다.

### 4.2 실시간 푸시(WebSocket) 미제공
- 일 1회 리밸런싱에는 영향이 거의 없습니다.
- 장중 매매로 확장하려면 REST 폴링을 써야 하고, 호출 제한 수치가 공개되지 않아 감시 종목 수와 주기를 **실측으로 정해야 합니다.**
- 대안: ① 폴링 주기를 설정값으로 두고 토큰버킷 방식으로 제한, ② 감시 종목을 소수(예: 보유종목 + 후보 10~20개)로 제한, ③ KB가 실시간 API를 내놓으면 데이터 피드 어댑터만 교체.

### 4.3 환전 API 없음 + 통합증거금(글로벌원마켓)
- 해외주식 주문은 "글로벌원마켓" 기반이라, 계좌 설정에 따라 **원화로 해외주식을 사는 통합증거금이 쓰일 수 있습니다.** (`fcrncy_unty_ordr_psbl_amt`, `krw_unty_mgn_rqst_f` 등의 필드가 있음)
- KRW/USD 분리 관리를 위한 대응:
  1. 사용자 측: 계좌의 **원화 통합증거금(원화주문) 서비스를 해지하거나 사용하지 않도록 설정**하는 것을 권장합니다. (설정 가능 여부는 KB 확인 필요)
  2. 시스템 측: 미국 주문 전에 `SKQM2106`의 **순수 외화주문가능금액(`fcrncy_ordr_psbl_amt`)**과 내부 USD 장부 잔액 중 작은 값까지만 주문하고, 통합주문가능금액은 쓰지 않습니다. 소수점 주문은 `crncy_ccd=1(USD)`로 고정합니다.
  3. 환전은 시스템이 하지 않습니다. 사용자가 수동으로 환전하면 다음 대사(reconciliation) 때 "외부 환전 이벤트"로 기록합니다.

### 4.4 기타
- **데이터 범위:** 재무제표·뉴스·장기 과거 데이터(상장폐지 종목 포함)는 KB API로 부족합니다 → DART, SEC EDGAR, pykrx/FinanceDataReader 등 외부 소스를 백테스트용으로 씁니다. KB 데이터와 교차 검증합니다.
- **장마감 주문:** 미국 LOC/MOC가 없습니다 → 일 1회 리밸런싱은 "예약주문(개장 시 실행)" 또는 "개장 후 지정가/VWAP"로 설계합니다.
- **IP/MAC 헤더:** 고정 IP 서버에서 운영하는 것이 유리합니다. 토큰과 네트워크 정보의 바인딩 여부는 KB에 확인이 필요합니다.

## 5. KB증권에 문의해 확인할 사항
1. 테스트(모의) 환경 제공 계획과 일정
2. 호출 제한 수치(초당/분당, API별)
3. 앱키 1개로 여러 계좌 사용 가능 여부, 계좌 지정 방식
4. 실시간 시세(WebSocket) 제공 계획
5. `ipAddr`/`macAddr` 헤더 검증 방식(토큰 바인딩 여부, 클라우드 서버 사용 가능 여부, 사전 IP 등록 필요 여부와 등록 가능 개수)
6. 원화 통합증거금 해지 가능 여부, 해외주문 시 결제 통화 지정 방법
7. 시세가 지연 시세인 조건(실시간 시세 신청 필요 여부)
8. Open API 약관상 자동매매·AI 매매에 제한이 있는지
9. (추가) 주문 시 사용자 지정 주문 ID(client order id)를 넣을 방법이 있는지, 응답이 유실됐을 때 권장하는 확인 방법
10. (추가) API 사용 신청 때 **조회 권한만** 따로 신청할 수 있는지(주문 권한 제외)
11. (추가) 일반 주문의 유효기간(당일 한정 여부), 기간 주문·GTC 지원 여부
12. (추가) 해외 소수점 주문의 최소 금액, 대상 종목, 체결 시점(즉시/묶음), 가격 결정 방식
13. (추가) SPQN5472 입력 항목(명세에는 INPUT이 비어 있음)
14. (추가) Open API 이용료 유무, 베타 종료 후 정책
