> 최종 수정일: 2026-10-30 (v0.4 반영) · 관련 문서: [PLAN.md](../PLAN.md), [KB API 조사](kb-openapi-research.md), [기술 위험 검토](technical-risk-review.md)
>

> - **[확인]** 공식 문서나 1차 자료로 확인한 사실 (출처 표기)

## 1. 공통 원칙

1. **세 가지 실행 모드가 같은 코드를 씁니다.** 과거 백테스트, 실시간 모의투자, (잠금 상태의) 실거래 모두 전략·리스크·OMS·비용 모델 코드가 같습니다. 바뀌는 것은 시계(Clock), 데이터 피드, 체결 모델뿐입니다.
2. **과거 백테스트와 실시간 모의투자는 체결 모델이 다릅니다.** 과거 백테스트는 봉(OHLCV) 데이터로 체결을 **추정**하고, 실시간 모의투자는 KB 호가·체결 조회 데이터로 체결을 **시뮬레이션**합니다. 두 결과를 같은 것으로 취급하지 않습니다(2장, 3장).
3. **"현재가에 즉시 체결"은 어느 모드에서도 쓰지 않습니다.**
4. **호가 조회 결과는 체결 보장이 아닙니다.** 조회한 호가 잔량은 그 순간의 표본일 뿐이고, 다음 순간에는 취소되거나 다른 주문이 먼저 가져갈 수 있습니다. 호가 잔량은 "체결될 수 있는 수량의 **상한**"으로만 씁니다(3.3절).
5. **모든 데이터에 "알 수 있게 된 시각"을 붙입니다.** 레코드마다 `event_time`(사건 시각)과 `available_at`(시스템이 알 수 있었던 가장 이른 시각)을 두고, 의사결정 시각보다 `available_at`이 늦은 데이터는 접근 계층에서 예외를 발생시킵니다.
6. **불확실하면 불리한 쪽으로 가정합니다.** 수수료·세금·슬리피지·체결 가능성 모두 보수적으로 잡고, AI API 비용도 전략 비용으로 차감합니다.

## 2. 과거 백테스트

### 2.1 사용 데이터
- 일봉: KB 차트 API(국내 IVS11560, 미국 GSC10060, 1회 최대 5,000건 [확인]) + 외부 공급자(데이터 공급자 비교 문서)
- 분봉: KB 차트 API의 분봉 기능 [확인: 차트구분에 분봉 있음]. **과거 분봉을 얼마나 오래전까지 받을 수 있는지는 [미확인]**
- **과거 호가(order book) 데이터: 없음.** KB API는 현재 시점 호가만 제공하고 [확인: 호가 API에 과거 조회 입력 없음], 무료 공급자 중 과거 호가를 주는 곳은 확인하지 못했습니다.

### 2.2 체결 추정 규칙 [제안]

| 상황 | 규칙 |
|---|---|
| 의사결정과 주문 시점 | T-1일 종가 이후 데이터로 결정하고, T일 장 시작 후 일정 시간 뒤(예: 국내 09:05, 미국 개장 5분 뒤)에 주문 |
| 즉시 체결형 주문(보호 한도 지정가) | 주문 시각 이후 **첫 분봉의 시가**(분봉이 없으면 일봉 시가) + 스프레드 추정치의 절반 + 시장 충격 추정치 + 안전마진 |
| 대기형 지정가 주문 | 봉의 가격 범위가 지정가에 **닿기만 한 경우에는 체결하지 않습니다.** 지정가를 **최소 1틱 넘어서 거래된 경우**(매수: 저가 < 지정가)에만 체결 |
| 체결 수량 상한 | 봉 거래량 × 참여율 상한(백테스트 기본 **5%**, 실시간 모의투자 10%보다 엄격하게) |
| 봉 안의 가격 순서 | 봉 안에서 고가·저가 중 무엇이 먼저 나왔는지 모르므로, 한 봉에서 유리한 순서를 가정하지 않습니다(손절과 목표가가 같은 봉에 있으면 손절이 먼저라고 가정) |
| 갭 | 시가가 지정가를 건너뛰면 시가에 체결(유리한 지정가로 체결한 것으로 처리하지 않음) |
| 상·하한가, 거래정지 | 상한가 봉 매수, 하한가 봉 매도, 거래정지일 거래는 체결하지 않음 |
| 미체결 | 당일 장 마감까지 체결되지 않은 수량은 만료. 다음 리밸런싱에서 다시 계산 |

### 2.3 스프레드·슬리피지 추정 [제안]
- 스프레드 추정: 가격대별 호가 단위(최소 1틱) 또는 일중 고가·저가로 계산한 스프레드 추정치 중 **큰 값**
- 시장 충격: `k × 일간 변동성 × √(주문수량 / 20일 평균 거래량)` 형태의 보수적 모형(k는 모의투자 데이터로 보정)
- 안전마진: 국내 10bp, 미국 5bp를 추가(초기값)
- 실시간 모의투자 기간에 쌓인 호가·체결 데이터로 위 추정치를 **사후 보정**하고, 보정 전후 결과를 함께 기록합니다.

### 2.4 낙관적 결과 방지 장치 [제안]
1. 대기형 지정가 체결은 "가격을 넘어서 거래"된 경우에만 인정하고, 그 체결량도 참여율 상한을 적용
2. 주문 수량이 20일 평균 거래량의 1%를 넘으면 주문 자체를 거부(백테스트에서 대형 주문 체결 착시 방지)
3. 비용 2배, 참여율 절반, 체결 지연 1봉 추가의 **스트레스 시나리오** 결과를 기본 결과와 함께 보고
4. 대기형 지정가 체결에 많이 의존하는 전략(체결의 30% 이상이 대기형)에는 "체결 추정 의존" 경고를 붙임
5. 결과 보고서에 "과거 호가 없음 → 대기열 재현 불가" 한계를 자동으로 표기

### 2.5 과거 백테스트의 근본 한계
- **과거 호가 데이터가 없으면 그 시점의 주문 대기열(내 앞에 쌓여 있던 주문)을 정확히 재현할 수 없습니다.** 그래서 과거 백테스트의 지정가 체결 여부와 체결 시점은 추정치이며, 실제보다 좋게도 나쁘게도 나올 수 있습니다.
- 분봉에는 스프레드와 호가 잔량 정보가 없어서 체결 가격도 추정치입니다.
- 이 한계 때문에 과거 백테스트 결과는 **전략 후보를 거르는 용도**로 쓰고, 최종 판단은 실시간 모의투자 결과로 합니다.

### 2.6 과대평가 방지 항목

| 항목 | 설계 |
|---|---|
| **미래 데이터 누수** | ① 모든 데이터 접근을 `PointInTimeStore.get(as_of=결정시각)`으로만 허용하고 `available_at > as_of`이면 예외. ② 결정 시각과 체결 시각 분리(같은 봉의 종가로 결정하고 그 종가에 체결하는 것 금지). ③ "미래 데이터를 바꿔도 과거 결정이 바뀌지 않는다"는 테스트. ④ 수정주가는 신호 계산에만 쓰고 체결 가격은 원래 가격 사용 |
| **LLM 지식에 의한 누수** | 6.3절 |
| **생존편향** | 날짜별 그 시점의 상장 종목 목록으로 유니버스 구성(상장폐지 종목 포함). 상장폐지 종목이 빠진 데이터면 결과에 "생존편향 있음" 경고를 붙이고 승인 근거로 쓰지 않음 |
| **상장폐지 반영** | 사유별 처리. 합병·현금 인수는 최종 가격으로 청산. 부도·감사의견 거절 등은 정리매매 데이터가 있으면 그 가격, 없으면 **보수적으로 −100%**(설정). 거래정지 기간에는 매도 불가 |
| **액면분할·배당** | 기업행사 테이블(분할 비율, 배당락일, 지급일, 배당금). 분할은 권리락일에 수량·평균단가 조정. 배당은 **지급일에 원천징수 후 금액**을 해당 통화 장부에 입금. 실거래 대사에서는 KB 권리 발생내역(SRQM3051)과 대조 |
| **재무정보 공개 시점** | 국내는 DART 접수일시, 미국은 EDGAR 접수일시를 `available_at`으로 사용. 장중 공시는 다음 거래일 시가부터 사용. 정정공시 값은 정정 시점부터만 적용하고 최초 공시 값을 보존 |
| **뉴스 최초 공개 시각** | `published_at`과 `first_seen_at` 저장. 백테스트는 `published_at + 지연 버퍼(기본 30분)`부터 사용. 발행 시각이 날짜 단위뿐이면 다음 거래일 시가부터. 과거 발행 시각을 믿을 수 없는 공급자는 백테스트에 쓰지 않음 |
| **거래 비용·슬리피지** | 4장 비용 테이블 + 2.2~2.3절 체결 추정. 보고서에 총수익, 비용 차감 후 수익, 비용 비중, 스트레스 결과를 함께 표시 |
| **학습·검증·테스트 분리** | 시간 순서로 분할(무작위 분할 금지). 가장 최근 12개월은 **잠금 테스트 구간**으로 두고, 전략·파라미터 확정 후 한 번만 평가. 열람 기록을 DB에 남기고, 다시 열면 "재사용됨" 표시 |
| **Walk-forward 검증** | 예: 학습 3년, 검증 6개월, 6개월씩 이동. 각 구간에서 학습 구간 파라미터로 다음 구간을 평가하고 이어 붙인 결과를 주 성과로 사용 |
| **Out-of-sample 검증** | ① walk-forward, ② 잠금 테스트 구간, ③ 실시간 모의투자(전향적 검증). 최종 판단 근거는 ③ |
| **다중 검정 보정** | 시도한 전략·파라미터 조합 수를 자동 기록하고, 이를 반영한 보정 Sharpe(Deflated Sharpe Ratio)를 함께 보고 |
| **시장 상황별 성과** | ① 추세(지수가 200일 이동평균 위인지 아래인지), ② 변동성(VKOSPI·VIX 분위), ③ 주요 위기 구간(2020년 3월, 2022년 하락장 등)으로 나눠 지표를 따로 냄. 장부(KRW/USD)별로도 나눔 |

## 3. 실시간 모의투자 (자체 페이퍼 엔진)

### 3.1 전제
- KB증권 Open API에는 자동화할 수 있는 모의투자 서버가 공개되어 있지 않습니다. 공개된 접속 정보는 운영 환경 하나뿐입니다 [확인: KB 개발가이드].
- 따라서 **실제 시세는 KB 조회 API로 받고, 주문 접수·체결·잔고는 내부 엔진이 계산**합니다. 모의투자 프로세스는 실거래 주문 API를 호출할 수 없게 격리합니다(기술 위험 검토 7.1절).
- 사용하는 KB 조회 데이터 [확인: KB API 명세]
  - 국내: 현재가(IVU10140), 10단계 호가와 잔량(IVU10070), 시간대별 체결(IVU10080), 장운영상태(SZQM0771)
  - 미국: 현재가(GSS10030, 시세구분 `0:실시간/1:지연`), 10단계 호가와 수량·호가 시각(GSS10040), 체결(GSA10020)

### 3.2 구조
```
 [KB 조회 폴링] ──▶ MarketSnapshot(호가 10단계, 최근 체결, 시각, 지연여부)
                         │
 [OMS] ──주문──▶ PaperExchange ──▶ OrderBookSim(종목별)
                    │  ├─ 접수 검증(장시간·가격단위·가격제한·현금/수량·통화)
                    │  ├─ 지연 모델(접수/취소 지연 = 다음 스냅샷 이후 반영)
                    │  ├─ 체결 모델(즉시 체결형 / 대기형)
                    │  └─ 수수료·세금 계산
                    ▼
               체결 이벤트 ──▶ OMS ──▶ 장부(KRW/USD)
```

### 3.3 호가 데이터 해석 원칙
- 조회한 호가 잔량 = **그 시점에 보였던 수량**. 숨은 주문, 직후 취소, 다른 참가자의 선점 때문에 실제로 체결될 수 있는 수량은 이보다 적을 수 있습니다.
- 미국 주식은 여러 거래소에 호가가 나뉘어 있고, KB가 보여주는 10단계 호가가 어느 범위의 호가인지(통합 호가인지)는 [미확인]입니다.
- 그래서 엔진은 호가 잔량을 **체결 가능 수량의 상한**으로만 쓰고, 실제 체결 인정에는 아래의 추가 조건(다음 스냅샷 확인, 실제 체결 기록)을 요구합니다.

### 3.4 체결 모델 [제안]

| 항목 | 설계 |
|---|---|
| **호가 잔량과 주문 가격 비교** | 매수 지정가 ≥ 매도1호가(매도는 반대)이면 "즉시 체결형", 아니면 "대기형"으로 분류 |
| **즉시 체결형** | 주문 접수 후 **다음 스냅샷**(지연 반영)에서 반대편 호가를 1단계부터 차례로 소진. 각 단계의 체결 인정 수량 = min(직전 스냅샷 잔량, 다음 스냅샷 잔량) × 인정 비율(기본 50%). 두 스냅샷 모두에 그 가격 호가가 있어야 인정(잔량 지속성 확인). 지정가 또는 보호 한도(기본: 접수 시 중간가 ±1%)를 넘는 단계는 소진하지 않고, 남은 수량은 대기형으로 전환하거나 취소(주문 조건에 따름) |
| **대기형(체결 우선순위 추정)** | 가격·시간 우선 원칙을 가정합니다. 내 앞 대기 수량 = 접수 시점에 같은 가격에 보였던 잔량. 이후 그 가격에서 **실제로 체결된 수량**(체결 API 기록)만큼 앞 대기 수량을 줄입니다. 앞 주문의 취소로 순서가 당겨지는 효과는 기본적으로 **인정하지 않습니다**(보수적). 앞 대기 수량이 0이 된 뒤의 체결량부터 내 주문이 체결된 것으로 봅니다. 가격이 내 지정가를 넘어서 거래되면(매수 기준 더 낮은 가격 체결) 앞 대기 수량과 관계없이 체결 가능한 것으로 봅니다 |
| **체결 가능 수량 제한** | 폴링 구간마다 실제 체결량 × 참여율 상한(기본 10%)까지만 인정. 주문 수량이 20일 평균 거래량의 1%를 넘으면 리스크 계층이 거부하거나 분할 |
| **부분 체결** | 위 규칙에서 자연히 생기며 OMS의 `PARTIALLY_FILLED`로 관리 |
| **미체결** | 체결 조건을 만족하지 못한 수량은 대기. 당일 장 마감 시 남은 수량은 `EXPIRED` |
| **주문 취소** | 취소 요청은 다음 스냅샷부터 효력. 그 사이 체결된 수량은 유효(취소 전 체결 경합 재현). 정정도 같은 방식 |
| **슬리피지** | 호가 단계 소진에 따른 가격 충격 + 접수 지연(다음 스냅샷 기준) + 안전마진(기본 2bp) |
| **주문 유효기간** | 당일 유효(DAY)만 시뮬레이션(일반 주문 입력에 유효기간 필드 없음 [확인], 당일 유효라는 점은 [가정]). 예약주문은 "다음 거래일 개장 시 접수"로 처리. GTC 미지원 |
| **거래 시간·장외 시간** | 국내·미국 **정규장만**. 동시호가 구간(국내 08:30~09:00, 15:20~15:30)과 미국 개장·마감 전후 5분에는 신규 주문 금지. 시간외·NXT·미국 프리/애프터마켓·주간거래는 이후 확장. 장 시간 밖 주문은 거부 또는 예약주문으로 전환(설정). 휴장일·반일장은 캘린더로 처리 |
| **가격 제한·VI** | 국내 가격제한폭 도달, VI 발동 구간에는 체결 보류. 상한가 매수·하한가 매도는 실제 체결 기록이 있을 때만 |
| **지연 시세** | 미국 시세구분이 지연(`1`)이거나 시세 시각이 기준보다 오래되면 해당 종목 체결 중단 |
| **수수료·세금** | 4장 비용 테이블 |
| **가격 단위** | 4.2절 호가 단위 테이블로 주문 가격 검증 |
| **현금·수량 검증** | 매수: 예상 체결금액 × (1 + 가격 버퍼) + 수수료 + 세금 ≤ 장부 가용현금 − 미체결 매수 예약금. 매도: 수량 ≤ 보유 − 미체결 매도. 통화가 다르면 거부(KRW 장부는 원화만, USD 장부는 달러만). 미결제 매도대금 재사용 여부는 설정(`use_unsettled_proceeds`, 기본 false) |
| **미국 소수점 주문** | **기본 비활성(v0.4 확정)**. 설정으로 켜더라도 KB 확인 전에는 쓰지 않음 |
| **지원하지 않는 주문 유형** | VWAP/TWAP 시장가, 최유리·최우선·중간가, IOC/FOK(입력 가능 여부 미확인)는 1차 개발에서 제외. 전략 설정에서도 막음 |

- 순수 시장가 주문은 기본적으로 쓰지 않고 "보호 한도 지정가"를 기본으로 합니다. 모의투자와 실거래 사이의 차이가 가장 큰 곳이 시장가 체결이기 때문입니다.
- 모의투자 기간에는 호가 스냅샷과 체결 데이터를 모두 저장해, 나중에 체결 모델을 바꿔 다시 계산할 수 있게 합니다.

### 3.5 실시간 모의투자의 한계

| 차이 원인 | 영향 | 크기 추정 |
|---|---|---|
| 폴링 간격(수 초) 사이의 공백 | 체결 가격·여부 오차 | 대형주·소량 주문은 작고, 변동성이 큰 구간은 큼 [가정] |
| 실제 대기열 위치를 알 수 없음(숨은 주문, 취소, 다른 거래소) | 대기형 지정가 체결률 오차 | 실제와 10~30% 다를 수 있음 [가정, 검증 필요] |
| 가상 주문은 실제 호가를 바꾸지 않음 | 성과 과대평가 | 주문이 평균 거래량의 0.1% 미만이면 작음 [가정] |
| 동시호가·VI·서킷브레이커 | 체결 가격 오차 | 해당 구간 주문을 피하면 작음 [가정] |
| KB 고유의 주문 거부(증거금, 매매제한, 점검) | 실제로는 거부될 주문이 체결된 것으로 처리 | [미확인]. 오류 코드 목록이 비어 있음 [확인] |
| 실제 수수료·세금과 테이블 값의 차이 | 비용 오차 | 실거래 첫 달 거래내역으로 보정 [제안] |

보정 절차 [제안]
1. 모의투자 기간에 호가·체결 원본 데이터를 저장
2. 실거래 초기(소액·반자동)에는 같은 주문을 페이퍼 엔진에도 넣어 **주문 단위로 비교**(체결률, 체결가 차이, 소요 시간)
3. 차이를 바탕으로 인정 비율·참여율·안전마진을 보정하고 보정 이력을 남김

## 6. AI 성과 기여도 검증

### 6.1 비교 대상 [제안]

| 코드 | 방식 | AI 역할 |
|---|---|---|
| **A. 정량 단독** | 정량 엔진의 목표 비중을 그대로 사용 | 없음 |
| **B. LLM 단독** | 같은 유니버스와 원자료(가격 요약, 재무, 공시·뉴스 요약)만 LLM에 주고 LLM이 종목과 비중을 결정. 정량 점수는 주지 않음 | 전부 |
| **C. 하이브리드** | 정량 후보와 점수 + 뉴스·공시 요약 → LLM이 후보 안에서 제외/유지/비중 조정(±5%p 상한 × λ) | 조정만 |

같은 조건: 같은 유니버스, 의사결정 시각, 데이터 스냅샷, 리스크 규칙, 포트폴리오 제약, 비용 모델, 장부 크기. B와 C는 **AI 호출 비용을 성과에서 차감**합니다.

### 6.2 운영 방식
- 실시간 모의투자 기간에 A, B, C를 **서로 독립된 페이퍼 포트폴리오(그림자 장부)**로 동시에 운영합니다. 각각 KRW/USD 장부를 따로 가집니다.
- "주 전략"은 하나(초기값 C)이고 나머지는 비교용입니다.

### 6.3 LLM 백테스트 가능 기간 재검증

**근거 [확인]:** Anthropic 공식 모델 문서는 현재 모델들의 "신뢰할 수 있는 지식 기준 시점(Reliable knowledge cutoff)"과 "학습 데이터 기준 시점(Training data cutoff)"을 모두 **2026년 6월**로 표기합니다. 날짜(일) 단위 정보는 공개되어 있지 않습니다.

**판단**
1. 2026년 6월 이전 기간은 모델이 그 결과(주가 흐름, 실적, 사건)를 학습했을 수 있으므로 LLM 전략(B, C) 백테스트의 **유효 평가 기간으로 인정하지 않습니다.**
2. 2026년 7월 이후는 모델이 학습하지 않은 기간이므로 이론상 평가할 수 있습니다. v0.3의 "약 4개월"은 이 기준으로 2026-07 ~ 2026-10-30을 계산한 값입니다. 다만 다음 이유로 **확정 수치로 쓰지 않고 "약 4개월 이내, 정확한 범위 미확인"으로 고칩니다.**
   - 학습 데이터 종료 일자가 월 단위로만 공개되어 경계가 불분명합니다 → 7월 초 일부 기간은 안전 구간으로 제외하는 것을 권장합니다(예: 2026-07-15 이후만 사용) [제안].
   - "학습 데이터 기준 시점"이 공개된 것과 별개로, 학습 데이터에 그 이후 정보가 조금이라도 섞였는지는 외부에서 검증할 수 없습니다 [미확인].
   - 컷오프가 더 늦은 새 모델을 쓰면 유효 기간이 그만큼 줄어듭니다.
   - LLM에 넣는 입력 자체에 미래 정보가 섞일 수 있습니다(예: 나중에 수정된 기사, 사후 분석 기사). 이는 2.6절의 시점 통제로 막아야 합니다.
3. 4개월 남짓한 기간은 시장 상황이 한두 가지뿐이고 표본이 작아 **통계적으로 의미 있는 결론을 내기 어렵습니다.**

**결론 [제안]**
- LLM 전략의 과거 백테스트 결과는 **참고 자료로만** 쓰고, 승인 기준(PLAN 15장 G1~G3)의 근거로 쓰지 않습니다.
- LLM 성능의 **핵심 평가 수단은 전향적 실시간 모의투자**입니다. 판단을 내린 시점에 결과를 아무도 모르는 상태에서 기록하고, 나중에 결과와 비교합니다.
- 종목명·날짜를 가리는 방식은 보조 수단으로만 씁니다(누수를 완전히 막지 못함).

### 6.4 기여도 판정과 λ [v0.4 기본 설계]
- 일간 수익률 차이(C − A, B − A)에 블록 부트스트랩으로 신뢰구간을 구하고, 비용 차감 후 Sharpe, MDD, 변동성, 회전율, 비용 비중을 비교합니다.
- **AI 개입 강도 λ(0~1)**: 하이브리드 최종 비중 = 정량 비중 + λ × AI 조정값(**±5%p 상한 유지**).
  - 초기값 λ = 0.5(설정)
  - 자동 하향: 최근 60거래일 기준 C의 위험 대비 성과가 A보다 기준 이상 나쁘면 0.5 → 0.25 → 0 순서로 낮춤
  - 상향은 **사람 승인으로만**
  - λ 변경 이력과 이유를 모두 기록
- AI가 의미 있는 개선을 보이지 못하면 실거래는 A(정량 단독, λ=0)로 시작하는 것이 기본 권고입니다.

### 6.5 AI 판단 기록 항목 [v0.4 기본 설계]

판단 1건마다 아래 항목을 저장합니다. 하나라도 빠지면 그 판단은 매매에 쓰지 않습니다.

| 항목 | 내용 |
|---|---|
| 모델 식별자 및 버전 | API에 보낸 모델 ID와 응답에 기록된 모델 ID. 현재 Claude 모델 ID는 고정 스냅샷이라고 공식 문서에 명시됨 [확인]. 제공자 이름 포함 |
| 실행 시각 | 요청 시각과 응답 시각(UTC) |
| 프롬프트 버전 | 시스템 프롬프트·출력 스키마의 버전 ID와 내용 해시 |
| 입력 데이터 기준 시각 | 입력에 쓴 데이터의 `as_of`(가장 늦은 `available_at`)와 데이터 스냅샷 ID, 입력 해시 |
| 분석 결과 | 구조화 출력 원문(행동·비중 조정·근거·확신도·예측 방향과 기간), 토큰 사용량과 비용 |
| 최종 매매 신호 | λ와 리스크 계층을 거친 뒤의 최종 목표 비중과 주문 여부(AI 제안과 최종 신호의 차이를 비교 가능하게) |
| 실제 이후 성과 | 예측 기간(예: 5·20거래일)이 지난 뒤 자동 기록: 종목 수익률, 유니버스 대비 초과수익, 예측 적중 여부, AI 조정이 만든 손익 기여 |

- 집계 지표: 적중률, 확신도 구간별 적중률(캘리브레이션), Brier 점수, AI 조정값과 이후 수익률의 순위상관(IC), 손익 기여
- 대시보드에 "AI 판단 성적표"를 장부별·시장 상황별로 표시합니다.

## 7. 실험 관리 [제안]
- 실험마다 코드 커밋 해시, 설정 파일, 데이터 스냅샷 ID, 비용 테이블 버전, 모델 ID, 난수 시드를 저장합니다.
- 같은 입력이면 같은 결과가 나와야 합니다(LLM 응답은 저장된 응답을 다시 써서 재현).
- 잠금 테스트 구간 사용 기록과 시도 횟수 기록을 자동으로 남깁니다.
- LLM 실험에는 실험마다 비용 상한을 두고, 같은 입력은 다시 호출하지 않습니다(비용 추정 문서 3.4절).
