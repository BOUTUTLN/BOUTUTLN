## 1. 공통 원칙

1. **세 가지 실행 모드가 같은 코드를 씁니다.** backtest, paper, (잠금 상태의) live 모두 전략·리스크·OMS·비용 모델 코드가 같습니다. 바뀌는 것은 시계(Clock), 데이터 피드, 체결기(Fill model / Broker adapter)뿐입니다. [제안]
2. **"현재가에 즉시 체결"은 쓰지 않습니다.** 백테스트와 모의투자 모두 호가·거래량·지연을 반영한 체결 모델을 거칩니다. [제안]
3. **모든 데이터에 "알 수 있게 된 시각"을 붙입니다.** 레코드마다 `event_time`(사건 발생 시각)과 `available_at`(시스템이 알 수 있었던 가장 이른 시각)을 둡니다. 의사결정 시점보다 `available_at`이 늦은 데이터는 접근 계층에서 **예외를 발생**시킵니다. [제안]
4. **비용은 보수적으로 잡습니다.** 수수료·세금·슬리피지는 불확실하면 불리한 쪽으로 가정합니다. AI API 비용도 전략 비용으로 차감합니다. [제안]

## 2. 자체 모의투자(페이퍼) 엔진

### 2.1 전제
- KB증권 Open API에는 자동화할 수 있는 모의투자 서버가 없습니다. 공개된 접속 정보는 운영 환경 하나뿐입니다. [확인: KB 개발가이드]
- 따라서 **실제 시세는 KB 조회 API로 받고, 주문 접수·체결·잔고는 내부 엔진이 계산**합니다. 페이퍼 모드에서 KB 주문 API는 HTTP 계층의 허용 목록으로 호출 자체를 막습니다. [제안]
- 사용하는 KB 조회 데이터 [확인: KB API 명세]
  - 국내: 현재가(IVU10140), **10단계 호가와 잔량**(IVU10070), 시간대별 체결(IVU10080), 장운영상태(SZQM0771)
  - 미국: 현재가(GSS10030, 시세구분 `0:실시간/1:지연` 포함), **10단계 호가와 잔량**(GSS10040), 체결(GSA10020)
  - 소수점 주문 가능 금액·수수료율·예상 수량(SPQN5472, 조회 API)

### 2.2 구조
```
 [KB 조회 폴링] ──▶ MarketSnapshot(호가10단계, 최근 체결, 시각, 지연여부)
                         │
 [OMS] ──주문──▶ PaperExchange ──▶ OrderBookSim(종목별)
                    │  ├─ 접수 검증(장시간·가격단위·가격제한·현금/수량)
                    │  ├─ 지연 모델(접수/취소 지연)
                    │  ├─ 체결 모델(시장가: 호가 소진 / 지정가: 대기열 + 체결량 기반)
                    │  └─ 수수료·세금 계산
                    ▼
               체결 이벤트 ──▶ OMS ──▶ 장부(KRW/USD)
```

### 2.3 기능별 설계

| 기능 | 설계 | 근거 수준 |
|---|---|---|
| **시장가 주문** | 접수 시점 이후 **다음 스냅샷**의 반대편 호가를 1단계부터 소진합니다(지연 반영). 각 단계에서 보이는 잔량의 일부(기본 50%)만 내 몫으로 인정해 스냅샷 사이에 다른 주문이 먼저 채갈 가능성을 반영합니다. 10단계로 부족하면 남은 수량은 미체결로 남기고 다음 스냅샷에서 이어서 처리합니다. 보호 한도(기본: 접수 시 중간가 ±1%)를 넘으면 나머지는 취소합니다. | [제안] |
| **지정가 주문** | 접수 시 바로 체결 가능한 가격(매수 지정가 ≥ 매도1호가)이면 그 한도 안에서 시장가처럼 처리합니다. 그렇지 않으면 대기 주문이 되며, **대기열 위치**를 "접수 시 같은 가격대에 이미 쌓인 잔량"으로 잡습니다. 이후 그 가격에서 체결된 거래량만큼 대기열이 줄고, 대기열이 다 빠진 다음부터 체결량의 일정 비율(참여율 상한)까지만 체결합니다. 가격이 내 지정가를 **넘어서 거래되면**(매수 기준 더 낮은 가격에 체결) 대기열과 상관없이 체결 가능한 것으로 봅니다. | [제안] |
| **호가 스프레드** | 매수는 매도호가, 매도는 매수호가에서 체결되므로 스프레드는 자동 반영됩니다. 백테스트(호가 데이터 없음)에서는 가격대·유동성별 스프레드 모델(최소 1틱)을 씁니다. | [제안] |
| **슬리피지** | ① 호가를 여러 단계 소진하면서 생기는 가격 충격, ② 의사결정 시점부터 접수까지의 지연(다음 스냅샷 사용), ③ 추가 안전마진(기본 2bp)을 합산합니다. | [제안] |
| **거래량에 따른 체결 가능성** | 폴링 구간마다 체결량의 **참여율 상한**(기본 10%)까지만 체결합니다. 주문 수량이 20일 평균 거래량(ADV)의 1%를 넘으면 리스크 계층이 주문을 거부하거나 분할합니다. | [제안] |
| **부분 체결** | 위 모델에서 자연스럽게 생깁니다. 부분 체결 상태는 OMS 상태 머신의 `PARTIALLY_FILLED`로 관리합니다. | [제안] |
| **미체결 및 취소** | 취소 요청은 지연(기본: 다음 스냅샷)을 거쳐 반영됩니다. 그 사이에 생긴 체결은 유효하게 처리합니다(취소 전 체결 경합 재현). | [제안] |
| **주문 유효기간** | 국내·미국 모두 **당일 유효(DAY)**로만 시뮬레이션합니다. 국내 정규장 주문은 15:30 마감 때, 미국 주문은 미국 정규장 마감 때 남은 수량을 만료(`EXPIRED`) 처리합니다. 예약주문(국내 SSAM0831, 미국 SPAO2104)은 "다음 거래일 개장 시 접수"로 시뮬레이션합니다. GTC(취소 전까지 유효)는 지원하지 않습니다. | 주문 입력 명세에 유효기간 필드가 없음 [확인]. 일반 주문이 당일 유효라는 점은 [가정] |
| **거래 시간·장외 시간** | 초기 범위는 **국내 정규장, 미국 정규장만** 다룹니다. 장 시작·마감 동시호가 구간(국내 08:30~09:00, 15:20~15:30)과 미국 개장·마감 직후·직전 5분에는 신규 주문을 내지 않습니다. 시간외, NXT, 미국 프리·애프터마켓, 미국 주간거래는 이후 확장 범위입니다. 장 시간 밖의 주문은 거부하거나 예약주문으로 바꿉니다(설정). 휴장일·조기폐장(미국 반일장)은 캘린더로 처리합니다. | 국내 시간 구분값은 [확인: SSAM1802 `mkt_tm_clsf`], 구체적인 시각은 [가정: 거래소 규정으로 검증 필요] |
| **가격 제한·VI** | 국내 ±30% 가격제한폭과 변동성완화장치(VI) 구간에는 체결하지 않거나 단일가로 처리합니다. 상한가 매수·하한가 매도는 실제 체결량이 확인될 때만 체결합니다. | [가정: 규정 수치 검증 필요, VI 여부를 API로 감지할 수 있는지 미확인] |
| **수수료·세금** | 효력 발생일이 있는 **비용 테이블**(설정 파일)로 관리합니다(2.4절). | 2.4절 참고 |
| **미국 소수점 주문** | KB는 금액 또는 수량 기준 소수점 주문(SKAM2201, 지정가 또는 유사시장가, 수량 소수 6자리)을 지원합니다. 다만 **최소 주문금액, 대상 종목, 실제 체결 시점(즉시인지 묶음 처리인지)은 공식 명세에 없습니다.** 따라서 검증 전까지는 ① 대상 종목을 수동 허용 목록으로 관리하고, ② 체결 가격을 "접수 시 매도호가와 다음 스냅샷 매도호가 중 불리한 값 + 추가 슬리피지"로 잡고, ③ 수수료율은 조회 API(SPQN5472)의 `fee_r_p10`을 사용합니다. 기본값은 `allow_fractional=false`입니다. | 기능 존재와 필드는 [확인], 제약 조건은 [미확인] |
| **가격 단위(호가 단위)** | 시장·가격대별 호가 단위 테이블을 설정으로 관리하고, 주문 가격이 단위에 맞지 않으면 거부합니다. 국내(주식, 2023년 개편 기준): 2천원 미만 1원, 5천원 미만 5원, 2만원 미만 10원, 5만원 미만 50원, 20만원 미만 100원, 50만원 미만 500원, 그 이상 1,000원. ETF·ETN 단위는 별도 확인이 필요합니다. 미국: 1달러 이상 $0.01, 1달러 미만 $0.0001. | 국내 표는 [가정: KRX 시행세칙 원문으로 검증 필요]. 미국 Rule 612 기본 단위는 [확인]. 일부 종목 $0.005 단위 도입은 준수일이 2027년 11월로 연기됐다는 보도가 있음 [가정: SEC 원문 확인 필요] |
| **주문 가능 현금·수량 검증** | 매수: `예상 체결금액 × (1 + 가격 버퍼) + 수수료 + 세금 ≤ 장부 가용현금 − 미체결 매수 예약금`. 매도: `수량 ≤ 보유수량 − 미체결 매도수량`. 통화가 다르면 거부합니다(KRW 장부는 KRW만, USD 장부는 USD만). 매도대금을 같은 날 재매수에 쓸 수 있는지는 설정값(`use_unsettled_proceeds`)으로 둡니다. | 결제 주기: 미국 T+1 [확인: SEC 규정 2024], 국내 T+2 [가정]. KB에서 미결제 매도대금을 쓸 수 있는지는 [미확인] |

### 2.5 시장가 주문 사용 정책 [제안]
- 실거래로 전환한 뒤에도 **순수 시장가 주문은 기본적으로 쓰지 않고**, "보호 한도가 있는 지정가(즉시 체결 가능한 가격의 지정가)"를 기본으로 합니다. 시뮬레이션과 실제 사이의 차이가 가장 큰 부분이 시장가 체결이기 때문입니다.
- KB의 VWAP/TWAP 시장가, 최유리·최우선·중간가, IOC/FOK는 페이퍼 엔진에서 1차로 지원하지 않습니다. 시뮬레이션이 불가능한 주문 유형을 실거래에서만 쓰지 않도록, 전략 설정에서도 막습니다.

### 2.6 현실성과 한계 (실제 KB 주문과 달라질 수 있는 부분)

| 차이 원인 | 영향 방향 | 크기 추정 | 근거 |
|---|---|---|---|
| 폴링 간격(수 초)으로 생기는 스냅샷 사이의 공백 | 체결 가격·체결 여부 모두 오차 | 대형주·소량 주문은 작고, 변동성이 큰 구간은 큼 | [가정] |
| 대기열 위치를 정확히 알 수 없음(숨은 주문, 같은 가격 우선순위) | 지정가 체결률을 과대·과소 추정 | 수동형 지정가 체결 여부가 실제와 10~30% 다를 수 있음 | [가정] |
| 내 주문이 시장에 주는 충격(가상 주문은 호가를 실제로 바꾸지 않음) | 성과 과대평가 | 주문이 ADV의 0.1% 미만이면 작음 | [가정] |
| 동시호가·VI·서킷브레이커 | 체결 가격 오차 | 해당 구간 주문을 피하면 작음 | [가정] |
| KB 고유의 주문 거부(증거금, 매매제한, 시스템 점검) | 실제로는 체결되지 않을 주문이 체결된 것으로 처리됨 | 미확인 | 오류 코드 목록이 비어 있음 [확인] |
| 소수점 주문 체결 시점·가격 방식 | 체결가 오차 | 미확인 | 공식 명세에 제약 없음 [확인] |
| 지연 시세 | 오래된 가격에 체결 | 지연 시세를 감지하면 체결을 중단하므로 통제 가능 | 시세구분 필드 존재 [확인] |
| 실제 수수료·세금과 테이블 값의 차이 | 비용 오차 | 실거래 첫 달 거래내역(SWQA2301 등)으로 보정 | [제안] |

**정리하면** 초기 대상인 유동성 높은 대형주를 하루 1회, 지정가 위주, 소액으로 거래할 때 모의투자와 실거래의 차이는 주로 **"지정가가 체결됐는가"**에서 생기고, 체결가 차이는 상대적으로 작을 것으로 **추정**합니다. 이 추정은 검증되지 않았습니다. 그래서 다음 순서로 보정합니다. [제안]
1. 모의투자 기간에 호가 스냅샷과 체결 데이터를 모두 저장합니다(체결 모델을 다시 돌려볼 수 있게).
2. 실거래 초기(소액·반자동)에는 같은 주문을 페이퍼 엔진에도 동시에 넣어 **실제 결과와 시뮬레이션 결과를 주문 단위로 비교**합니다(체결률, 체결가 차이, 소요 시간).
3. 차이를 바탕으로 참여율, 대기열 가정, 안전마진을 보정하고 보정 내역을 기록합니다.

## 3. 백테스트 엔진

### 3.1 구조 [제안]
- 이벤트 기반 엔진: `Clock → 데이터 이벤트 → 전략 → 포트폴리오 → 리스크 → OMS → 체결 모델(백테스트용) → 장부`
- 백테스트 체결 모델: 과거 호가 데이터가 없으므로 일봉·분봉 OHLCV와 스프레드 모델을 사용합니다. 기본 규칙은 다음과 같습니다.
  - 의사결정은 T-1일 종가 이후 데이터로 하고, 주문은 T일 장 시작 후 일정 시간 뒤에 냅니다.
  - 체결 가격은 T일 시가(또는 지정 시각 VWAP 추정치)에 스프레드 절반과 충격비용을 더합니다.
  - 지정가는 그날 가격 범위 안에 있어도 **가격을 넘어서 거래된 경우에만** 체결합니다. 저가와 같은 가격이면 체결하지 않습니다.
  - 체결 수량은 그날 거래량의 참여율 상한까지만 인정합니다.
- 모의투자 기간에 쌓인 호가·체결 데이터로 백테스트 비용 모델을 보정합니다.

### 3.2 과대평가 방지 항목

| 항목 | 설계 |
|---|---|
| **미래 데이터 누수** | ① 모든 데이터 접근을 `PointInTimeStore.get(as_of=결정시각)`으로만 허용하고 `available_at > as_of`이면 예외를 냅니다. ② 의사결정 시각과 체결 시각을 분리합니다(같은 봉의 종가로 결정하고 그 종가에 체결하는 것을 금지). ③ 지표 계산 코드에 "미래 데이터를 바꿔도 과거 결정이 바뀌지 않는지" 확인하는 테스트를 넣습니다. ④ 수정주가는 신호 계산에만 쓰고 체결 가격은 원래 가격(raw)을 씁니다. |
| **LLM 지식에 의한 누수** | LLM은 학습 데이터에 과거 시장 결과가 들어 있을 수 있습니다. 따라서 **모델의 학습 컷오프 이후 기간만** LLM이 포함된 전략(B, C)의 유효한 평가 기간으로 인정합니다. 종목명·날짜를 가려서 넣는 방식은 보조 수단일 뿐 누수를 완전히 막지 못합니다. (4.3절 참고) |
| **생존편향** | 날짜별 **그 시점의 상장 종목 목록**으로 유니버스를 구성합니다(상장폐지 종목 포함). 상장폐지 종목이 빠진 데이터만 있으면 해당 결과에 "생존편향 있음" 경고를 붙이고 승인 근거로 쓰지 않습니다. |
| **상장폐지 반영** | 폐지 사유별로 처리합니다. 합병·현금 인수는 최종 가격으로 청산합니다. 부도·감사의견 거절 등은 정리매매 기간 데이터가 있으면 그 가격으로, 없으면 **보수적으로 -100%**(설정)로 처리합니다. 거래정지 기간에는 매도할 수 없는 것으로 처리합니다. |
| **액면분할·배당** | 기업행사 테이블(분할 비율, 배당락일, 지급일, 배당금)을 따로 둡니다. 분할은 배당락·권리락일에 보유수량과 평균단가를 조정합니다. 배당은 **지급일에 원천징수 후 금액**을 해당 통화 장부에 입금합니다. 실거래 대사에서는 KB 권리 발생내역(SRQM3051)과 대조합니다. |
| **재무정보 공개 시점** | 국내는 DART 접수일시, 미국은 EDGAR 접수일시(acceptance datetime)를 `available_at`으로 씁니다. 장중에 공시되면 **다음 거래일 시가부터** 사용합니다(보수적). 정정공시로 바뀐 값은 정정공시 시점부터만 적용하고, 처음 공시된 값을 그대로 보존합니다(시점별 재무 데이터). |
| **뉴스 최초 공개 시각** | `published_at`(공급자가 제공한 발행 시각), `first_seen_at`(시스템이 처음 수집한 시각)을 저장합니다. 백테스트는 `published_at + 지연 버퍼(기본 30분)`부터 사용합니다. 발행 시각이 날짜 단위뿐이면 다음 거래일 시가부터 사용합니다. 과거 뉴스의 발행 시각을 믿을 수 없는 공급자는 백테스트에 쓰지 않습니다. |
| **거래 비용·슬리피지** | 2.4절 비용 테이블과 3.1절 체결 모델을 적용합니다. 결과 보고서에 **총수익, 비용 차감 후 수익, 비용 비중**을 함께 표시합니다. 비용을 2배로 했을 때의 민감도 결과도 같이 냅니다. |
| **학습·검증·테스트 분리** | 시간 순서로 나눕니다(무작위 분할 금지). 가장 최근 구간(예: 12개월)은 **잠금 테스트 구간(lockbox)**으로 두고, 전략과 파라미터를 확정한 뒤 **한 번만** 평가합니다. 잠금 구간을 열어본 기록은 DB에 남기고, 다시 열면 결과에 "재사용됨"을 표시합니다. |
| **Walk-forward 검증** | 예: 학습 3년, 검증 6개월, 6개월씩 이동. 각 구간(fold)에서 학습 구간 파라미터로 다음 구간을 평가하고, 이어 붙인 결과를 주 성과로 봅니다. |
| **Out-of-sample 검증** | ① walk-forward 결과, ② 잠금 테스트 구간, ③ 실제 모의투자(전방 검증) 세 겹으로 확인합니다. 모의투자 결과가 최종 판단 근거입니다. |
| **다중 검정 보정** | 시도한 전략·파라미터 조합 수를 실험 기록에 자동으로 남기고, 시도 횟수를 반영한 보정 Sharpe(Deflated Sharpe Ratio)를 함께 보고합니다. |
| **시장 상황별 성과** | 기간을 ① 추세(지수가 200일 이동평균 위인지 아래인지), ② 변동성(VKOSPI·VIX 분위), ③ 주요 위기 구간(2020년 3월, 2022년 하락장 등)으로 나눠 지표를 따로 냅니다. 장부(KRW/USD)별로도 나눕니다. |

### 3.3 성과 지표 정의 [제안]

| 지표 | 정의 |
|---|---|
| CAGR | (최종 NAV / 최초 NAV)^(1/연수) − 1 |
| MDD | 최고점 대비 최대 하락률 |
| 변동성 | 일간 수익률 표준편차 × √252 |
| Sharpe Ratio | (연환산 수익률 − 무위험수익률) / 연환산 변동성. 무위험수익률: KRW 장부는 CD 91일물, USD 장부는 미국 3개월 국채 |
| Sortino Ratio | (연환산 수익률 − 무위험수익률) / 하방 편차 |
| 승률 | 청산된 포지션 단위(FIFO 매칭)에서 이익인 비율. 리밸런싱 기간 단위 승률도 함께 표시 |
| 평균 손익비 | 평균 이익 / 평균 손실(절댓값) |
| Profit Factor | 총이익 / 총손실(절댓값) |
| 거래 회전율 | 연간 (매수금액 + 매도금액) / 2 / 평균 NAV |
| 시장 대비 초과수익률 | 전략 수익률 − 벤치마크 수익률(같은 비용 반영). 추적오차와 정보비율(IR)도 함께 표시 |
| 비용 비중 | (거래비용 + AI 비용) / 총수익 |
| Calmar | CAGR / MDD |

## 4. AI 성과 기여도 검증

### 4.1 비교 대상 [제안]

| 코드 | 방식 | AI 역할 |
|---|---|---|
| **A. 정량 단독** | 정량 엔진의 목표 비중을 그대로 사용 | 없음 |
| **B. LLM 단독** | 같은 유니버스와 원자료(가격 요약, 재무, 공시·뉴스 요약)만 LLM에 주고, LLM이 직접 종목과 비중을 결정. 정량 점수는 주지 않음 | 전부 |
| **C. 하이브리드** | 정량 후보와 점수 + 뉴스·공시 요약 → LLM이 후보 안에서 제외/유지/비중 조정(±5%p 상한) | 조정만 |

**같은 조건**: 같은 유니버스, 같은 의사결정 시각, 같은 데이터 스냅샷, 같은 리스크 규칙·포트폴리오 제약·비용 모델·장부 크기. B와 C는 **AI 호출 비용을 성과에서 차감**합니다.

### 4.2 운영 방식 [제안]
- 모의투자 기간에 A, B, C를 **서로 독립된 페이퍼 포트폴리오(그림자 장부)**로 동시에 운영합니다. 각각 KRW/USD 장부를 따로 가집니다.
- 실제 "주 전략"은 하나(초기값 C)이고 나머지는 비교용입니다. 실거래 승인 때는 이 비교 결과로 어느 방식을 쓸지 정합니다.

### 4.3 LLM 평가 기간의 한계 (중요)
- 최신 LLM의 학습 데이터 컷오프는 대체로 2026년 중반으로 추정됩니다. [가정: 운영에 쓸 모델의 공식 컷오프를 모델별로 확인 필요] 컷오프가 2026년 6월이라면 **오늘(2026-10-30) 기준으로 유효한 LLM 백테스트 기간은 약 4개월**밖에 되지 않습니다.
- 그래서 B와 C의 판단은 **백테스트보다 전방 모의투자 결과를 중심으로** 해야 합니다. 3개월 모의투자만으로는 통계적 유의성이 약하다는 점을 승인 기준(PLAN 11장)에 반영했습니다.
- 운영 중에 **모델을 바꾸면 비교 기록이 이어지지 않습니다.** 모델 ID를 고정하고, 바꿀 때는 새 모델을 그림자 장부로 일정 기간 함께 돌린 뒤 바꿉니다.

### 4.4 기여도 판정 [제안]
- 일간 수익률 차이(C − A, B − A)에 대해 블록 부트스트랩으로 신뢰구간을 구하고, 비용 차감 후 Sharpe, MDD, 변동성, 회전율, 비용 비중을 함께 비교합니다.
- **AI 개입 강도 λ(0~1)**: 하이브리드의 최종 비중 = 정량 비중 + λ × (AI 조정값, ±5%p 상한).
  - 자동 하향: 최근 60거래일 기준 C가 A보다 위험 대비 성과가 나쁘고 그 차이가 일정 기준을 넘으면 λ를 단계적으로 낮춥니다(0.5 → 0.25 → 0). λ가 0이면 A와 같아집니다.
  - 상향은 **사람의 승인으로만** 합니다(자동으로 키우지 않음).
  - λ가 바뀐 이력과 이유를 모두 기록합니다.
- AI가 통계적으로 의미 있는 개선을 보이지 못하면 실거래는 **A(정량 단독)**로 시작하는 것을 기본 권고로 합니다.

### 4.5 LLM 판단 추적 [제안]
- 판단 1건마다 기록: 모델 ID, 프롬프트 버전, 입력 해시, 출력(행동·비중·근거·확신도), **예측 내용(기간 h 동안 유니버스 대비 초과/미달)**, 비용
- 기간 h가 지나면 자동 평가: 적중률, 확신도 구간별 적중률(캘리브레이션), Brier 점수, AI 조정값과 이후 수익률의 순위상관(IC), AI 조정으로 생긴 손익 기여
- 대시보드에 "AI 판단 성적표"를 장부별·시장 상황별로 표시합니다.

## 5. 실험 관리 [제안]
- 실험마다 코드 커밋 해시, 설정 파일, 데이터 스냅샷 ID, 비용 테이블 버전, 모델 ID, 난수 시드를 저장합니다.
- 같은 입력이면 같은 결과가 나와야 합니다(LLM 응답은 저장된 응답을 다시 써서 재현).
- 잠금 테스트 구간 사용 기록, 시도 횟수 기록을 자동으로 남깁니다.
