## 0. 전제와 원칙

- **수익은 보장되지 않습니다.** 1차 목표는 "검증할 수 있고, 손실이 생겨도 정해진 범위 안에서 통제되는 시스템"입니다.
- **AI는 매매를 제안만 하고 최종 결정권은 갖지 않습니다.** 주문은 모두 고정 규칙으로 된 리스크 관리 계층을 통과해야 나가며, 이 계층은 AI가 건너뛸 수 없습니다.
- **AI가 성과를 개선한다고 가정하지 않습니다.** 정량 단독, LLM 단독, 하이브리드를 같은 조건에서 비교하고, 개선이 확인되지 않으면 AI 개입을 줄이거나 없앱니다.
- **LLM의 과거 백테스트 성과를 신뢰하지 않습니다.** LLM 성능은 전향적 모의투자로 평가합니다(9장).
- **증권사는 KB증권 Open API로 고정합니다.** 기능 제약이 있으면 다른 증권사로 바꾸지 않고, 대안을 보고한 뒤 결정을 받습니다.
- **초기 개발은 백테스트와 모의투자만 합니다.** 실거래 기능은 기본 잠금이며, 별도 승인 전까지 코드·설정·자격증명·배포 모든 단계에서 비활성화합니다(6장).
- **브로커가 제공하지 않는 기능을 제공한다고 가정하지 않습니다.** 예: KB API에는 사용자 지정 주문 ID가 없으므로, 브로커 수준의 멱등성은 없다는 전제로 설계합니다(10장).
- **킬 스위치는 자동 청산을 하지 않습니다.** 기본 동작은 신규 주문 차단입니다(10장).
- **Claude Cloud는 개발 전용입니다.** 모의투자와 실거래는 별도의 국내 운영 서버에서만 실행합니다(13장).

## 2. KB증권 Open API 조사 결과 요약

**지원되는 것 [확인]:** 국내·미국 시세/차트(틱~년봉, 수정주가), 10단계 호가와 잔량, 주문·정정·취소, 예약주문, 소수점 주문, 잔고·체결·손익 조회, 통화별 예수금·주문가능금액, 환율 조회, 장운영상태

**제약 사항과 계획 반영 방식:**

| 제약 [확인] | 계획 반영 (증권사 변경 없음) |
|---|---|
| 모의투자 API 환경 공개 안 됨 | 자체 모의투자 엔진 [확정](8장) |
| **해외 IP 접속·API 호출 차단**(2026-10-28 공지) | 국내 리전 고정 IP 운영 서버, 사전 접속 확인, 국내 클라우드 사업자 대안(13장) |
| 실시간 푸시 없음, 호출 제한 수치 비공개 | 폴링 + 토큰버킷 제한기, 시세 신선도 검사 |
| 환전 API 없음, 통합증거금 구조 | 통합증거금 사용 금지, 순수 외화 주문가능금액만 사용, 환전은 사용자가 수동으로 |
| 재무·뉴스 부족, 차트 1회 5,000건 | 외부 데이터 공급자 + Data Provider 인터페이스(11장) |
| 미국 LOC/MOC 없음 | 예약주문(개장 시 실행) 또는 개장 후 지정가 |
| 오류 코드 목록 없음 | `o_clsf`/`o_msg` 기반 공통 파서, 알 수 없는 응답은 결과 불명 처리 |
| 오픈베타 | 명세 정기 수집·내용 해시 비교 |
| 사용자 지정 주문 ID 없음 | 브로커 멱등성 없음을 전제로 내부 통제 + 확인 불가 시 거래 중단(10장) |
| 주문 유효기간·GTC 입력 없음 | 당일 유효 주문만 사용한다고 가정, KB 확인 |
| 소수점 주문 제약이 명세에 없음 | 미국 소수점 주문 기본 비활성 [확정] |

**공식 자료에 없는 것 [미확인]:** IP 사전 등록(화이트리스트) 제도, 고정 IP 요구, 클라우드 IP 판정 방식, `ipAddr`/`macAddr` 값 기준과 검증 방식, 조회 전용 권한 신청 가능 여부. → KB 문의(조사 보고서 5장, 7.4절)

```
                         ┌───────────────────────────────┐
                         │   스케줄러 / 이벤트 루프        │
                         │ (시장별 거래 캘린더·시간대 인식) │
                         └──────────────┬────────────────┘
                                        │ 이벤트(장 시작 전, 봉 마감, 체결 등)
 ┌──────────────┐  ┌─────────────┐  ┌──▼───────────┐  ┌──────────────┐
 │① 데이터 계층  │─▶│② 정량 엔진   │─▶│③ AI 분석      │─▶│④ 포트폴리오   │
 │DataProvider  │  │ 팩터·시그널  │  │ AIProvider   │  │ 구성(목표비중)│
 │(KB·외부, PIT)│  └─────────────┘  │ (λ 개입 강도) │  └──────┬───────┘
 └──────────────┘                   └──────────────┘         │
                     ┌──────────────── 통화별 장부 ────────────▼────────┐
                     │ ⑤ 리스크 관리 (KRW 규칙 │ USD 규칙 │ 전체 통합 규칙) │ ← AI 우회 불가
                     └──────────────────────────┬──────────────────────┘
                                                │ 승인된 주문
 ┌─────────────┐   ┌──────────────┐  ┌──────────▼───────────────────────────┐
 │⑧ 대시보드·알림│◀──│⑦ 기록·감사·대사│◀─│⑥ OMS(상태 머신) → 브로커 어댑터          │
 │ 텔레그램·웹  │   │ DB·근거·비용  │  │ BacktestBroker │ PaperBroker │ KBLive(잠금)│
 └─────────────┘   └──────────────┘  └──────────────────────────────────────┘
```

### 핵심 설계 원칙
- **실행 모드에 상관없이 같은 전략·리스크·OMS 코드:** 시계·데이터 피드·체결 모델·브로커 어댑터만 `backtest` / `paper` / `live`에 따라 바뀝니다.
- **실행 모드별 배포 격리:** `paper`와 `live`는 별도 프로세스·서비스·DB·인증정보로 운영합니다. `paper` 이미지에는 KB 주문 모듈이 없습니다(6장, 13장).
- **이벤트 기반:** 일 1회 리밸런싱은 "일봉 이벤트에서 1번 실행"하는 설정이고, 장중 매매는 분봉 이벤트를 구독하는 방식으로 확장합니다.
- **시장·통화별 분리:** `Market(KR, US)`, `Currency(KRW, USD)`, `Book(장부)`, `Money(금액+통화)`를 1급 개념으로 다룹니다.
- **시점 정합성:** 모든 데이터에 `available_at`을 붙이고, 의사결정 시각보다 늦은 데이터는 접근 계층에서 차단합니다.

### 구성요소
- **① 데이터 계층:** KB 조회 어댑터(조회 전용 엔드포인트만 허용, 국내 운영 서버에서만 실행) + 외부 공급자. 역할별 Provider 인터페이스, 우선순위 대체, 사용량 관리, 원본 저장(11장)
- **② 정량 엔진:** 유니버스 필터(거래대금 하한, 관리·거래정지·매매제한 종목 제외), 팩터(모멘텀·가치·퀄리티·저변동성), (선택) ML은 walk-forward 검증 필수
- **③ AI 분석:** 정량 후보 안에서만 판단(후보 밖 신규 종목 추가 금지), 출력은 종목별 `제외 / 유지 / 비중 조정` + 근거 + 확신도 + 예측(JSON 스키마 고정), **±5%p 상한 × AI 개입 강도 λ** [확정 C1], 실패 시 정량 단독 진행 또는 매매 보류(설정), 모델 ID 고정, 프롬프트 버전 관리, 판단 기록(9장)
- **④ 포트폴리오 구성:** 장부별 목표비중(동일가중 / 점수가중 / 변동성 역가중 중 선택), 최소 리밸런싱 기준·최소 주문금액·비용 대비 기대수익 검사(14장)
- **⑤ 리스크 관리:** 장부별 규칙 + 전체 통합 규칙(14장). 가격 상·하한, 호가 단위, 장 운영시간, 통화 검사(KRW 장부는 원화 현금만, USD 장부는 달러 현금만)
- **⑥ OMS:** 상태 머신, 내부 중복 방지 통제, 응답 유실 처리, 재시작 복구(10장)
- **⑦ 기록·감사:** 시세, 시그널, AI 판단 기록·비용, 목표비중, 주문 상태 이력, 체결, 장부 스냅샷, 대사 결과, 환율
- **⑧ 모니터링:** 텔레그램(체결·일일 리포트·경고·긴급·명령), 대시보드(장부별 성과, 통합 보기, AI 판단 성적표)

## 5. KRW / USD 장부 완전 분리 [확정]

| 항목 | KRW 장부 | USD 장부 |
|---|---|---|
| 대상 | 국내 주식 | 미국 주식 |
| 현금 | 원화 예수금 | 외화(USD) 예수금 |
| 성과 측정 | 원화 기준 | 달러 기준(환율 효과는 별도 표시) |
| 벤치마크 | KOSPI(또는 KOSPI200) | S&P500 |
| 리스크 한도 | 장부별로 따로 | 장부별로 따로 |
| 대사 | 원화 예수금·국내 잔고 | 외화 예수금·해외 잔고 |
| 비용·세금 | 증권거래세, 국내 수수료 | 해외 수수료, SEC 수수료, FINRA TAF, 양도소득세 기록 |

- 금액은 `Money(amount: Decimal, currency)` 타입으로만 다루고, 통화가 다른 금액끼리 계산하면 오류가 납니다.
- **통합증거금 사용 금지:** 미국 주문 가능 금액 = min(USD 장부 현금, KB 순수 외화주문가능금액 `fcrncy_ordr_psbl_amt`). 통합주문가능금액·원화환산 주문가능금액은 쓰지 않습니다. 대사 때 원화 예수금이 해외 주문에 쓰였는지 검사하고, 쓰였으면 USD 장부를 정지합니다. 계좌의 원화 통합증거금 서비스를 해지할 수 있는지는 KB에 확인합니다.
- 시스템은 환전하지 않습니다. 사용자가 직접 환전하면 대사 과정에서 외부 이벤트로 등록합니다.
- 원화 환산 통합 보기는 위험 평가와 보고에 쓰고, 개별 매매 판단에는 쓰지 않습니다.

### 초기 모의투자 자금 설정 [확정: 설정 파일로 변경 가능]

# config/paper.yaml (예시)

  KRW:
    initial_cash: 10000000      # 원

  USD:
    initial_cash: 7000.00       # 달러

## 6. 실거래 기본 잠금 [확정]

1. **설정:** `trading.mode` 기본값은 `backtest`, 허용은 `paper`까지. `live`는 설정 검증에서 거부합니다.
2. **코드:** `KBLiveBroker`는 ① 환경변수 `LIVE_TRADING_ENABLED=true`, ② 사용자가 작성한 승인 파일(승인일·한도), ③ 장부별 실거래 한도가 모두 있어야 생성됩니다.
3. **HTTP 계층:** 엔드포인트 허용 목록. paper/backtest 모드에서는 주문 API(SSAM*, SKAM*, SPAO* 등) 요청을 만들기 전에 거부합니다.
4. **배포 격리 [확정 C7]:** 모의투자와 실거래는 같은 클라우드 인프라에 둘 수 있지만 **별도 프로세스·서비스·데이터베이스·인증정보**로 분리합니다. 모의투자 이미지는 KB 주문 모듈 없이 빌드합니다. 실거래 서비스는 승인 전까지 배포하지 않습니다.
5. **테스트:** "paper 모드·paper 이미지에서 주문 엔드포인트가 호출될 수 없다"는 테스트를 CI에 넣습니다.
6. **API 권한:** 모의투자 서비스에는 조회 권한만 있는 자격증명을 두는 방안을 KB에 확인합니다(가능 여부 [미확인]). 불가능하면 남는 위험을 G5 승인 조건에 명시합니다.
7. **환경 분리:** 개발 환경(Claude Cloud 포함)에는 KB 키를 두지 않습니다.
8. **실거래 첫 단계(승인 후):** 소액 한도 + 주문마다 텔레그램으로 사람이 승인하는 반자동 모드.

## 8. 백테스트와 실시간 모의투자 (요약)

상세: [백테스트 및 모의투자 설계 2~3장](docs/backtesting-design.md)

**공통:** 현재가 즉시 체결은 쓰지 않습니다. **호가 조회 결과를 체결 보장으로 해석하지 않습니다** — 조회한 잔량은 체결 가능 수량의 상한일 뿐입니다.

| 구분 | 과거 백테스트 | 실시간 모의투자 |
|---|---|---|
| 데이터 | 과거 일봉·분봉(과거 분봉 보관 기간 [미확인]) | KB 10단계 호가·체결 조회(폴링) |
| 과거 호가 | **없음** → 대기열 재현 불가 | 현재 호가 사용 |
| 즉시 체결형 | 다음 봉 시가 + 스프레드 절반 + 시장 충격 + 안전마진 | 다음 스냅샷의 반대편 호가 소진, 두 스냅샷에 모두 있는 잔량의 일부만 인정 |
| 대기형 지정가 | 지정가를 1틱 이상 넘어서 거래된 경우만 체결 | 가격·시간 우선 가정, 앞 대기 수량을 실제 체결량으로만 차감(취소로 당겨지는 효과 미인정) |
| 체결 수량 상한 | 봉 거래량의 5% | 폴링 구간 체결량의 10% |
| 부분 체결·미체결·취소 | 봉 단위로 처리, 장 마감 시 만료 | 스냅샷 단위로 처리, 취소는 다음 스냅샷부터 효력 |
| 낙관 방지 | 스트레스 시나리오(비용 2배, 참여율 절반, 체결 1봉 지연), 체결 추정 의존 경고 | 지연 시세·오래된 시세면 체결 중단, 보정 데이터 저장 |
| 수수료·세금 | 효력일 있는 비용 테이블(공통) | 동일 |

- **과거 호가 데이터가 없으면 과거 주문 대기열을 정확히 재현할 수 없습니다.** 그래서 과거 백테스트는 전략 후보를 거르는 용도이고, 최종 판단은 실시간 모의투자로 합니다.
- 실거래 초기에는 같은 주문을 페이퍼 엔진에도 넣어 주문 단위로 비교·보정합니다.

## 9. 성과 검증과 AI 기여도 (요약)

상세: [백테스트 및 모의투자 설계 2.6절, 5~6장](docs/backtesting-design.md)

- **과대평가 방지:** 시점별 데이터 접근 강제, 결정·체결 시각 분리, 생존편향 방지, 상장폐지 사유별 처리, 분할·배당은 기업행사 테이블, 재무는 공시 접수 시각, 뉴스는 최초 공개 시각 + 지연 버퍼, 비용·슬리피지(스트레스 포함), 시간 순서 분할과 잠금 테스트 구간, walk-forward, OOS 3단계, 다중 검정 보정, 시장 상황별 성과
- **지표:** CAGR, MDD, Sharpe, Sortino, 승률, 평균 손익비, Profit Factor, 회전율, 시장 대비 초과수익률(+ 변동성, IR, Calmar, 비용 비중)
- **비교 기준:** B0 지수 추종, B1 동일가중, B2 단순 모멘텀, B3 저변동성
- **AI 기여도:** A(정량 단독), B(LLM 단독), C(하이브리드)를 같은 조건에서 비교. 모의투자 기간에 세 가지를 독립된 그림자 장부로 동시에 운영. AI 비용은 성과에서 차감
- **AI 개입 강도 λ [확정 C1]:** 최종 비중 = 정량 비중 + λ × AI 조정(±5%p 상한 유지). 초기값 0.5, 성과가 나쁘면 자동 하향(0까지), 상향은 사람 승인으로만
- **LLM 백테스트 재검증:** 현재 모델의 학습 데이터 기준 시점은 2026년 6월 [확인: Anthropic 모델 문서]이지만 일자 단위 정보와 세부 범위는 [미확인]입니다. 이론상 평가 가능한 기간은 2026년 7월 이후 몇 개월 이내이며 확정 수치로 쓰지 않습니다. **LLM 과거 백테스트 결과는 참고용이고, LLM 성능의 핵심 평가는 전향적 모의투자입니다.**
- **AI 판단 기록(판단 1건마다):** 모델 식별자 및 버전, 실행 시각, 프롬프트 버전, 입력 데이터 기준 시각, 분석 결과, 최종 매매 신호, 실제 이후 성과. 하나라도 빠지면 그 판단은 매매에 쓰지 않음

## 10. 주문 실행·장애 복구·킬 스위치 (요약)

상세: [기술 위험 검토 2~5장](docs/technical-risk-review.md)

> **KB증권 API는 사용자 지정 주문 ID를 지원하지 않습니다 [확인].** 따라서 브로커 수준의 멱등성은 없고, 아래 장치는 시스템 내부에서 중복 주문 위험을 **줄이고 감지**하는 통제입니다. 모든 장애 상황에서 중복 주문이 없다고 보장하지는 않습니다.

- **상태 머신:** DRAFT → APPROVED → SUBMITTING → ACKNOWLEDGED → PARTIALLY_FILLED → FILLED / CANCEL_PENDING → CANCELLED / REJECTED / EXPIRED / UNKNOWN → (확인) / FAILED_NOT_SENT
- **내부 통제:** 결정적 내부 주문 ID + DB 유일성 제약(시스템 내 중복 생성 방지), 송신 전 기록, 종목당 활성 주문 1개, 주문 API 자동 재전송 금지
- **응답 유실 규칙 [확정]:**
  1. 상태를 `UNKNOWN`으로 변경
  2. 해당 종목의 신규 주문 차단
  3. 미체결 및 체결 내역 조회
  4. 계좌 잔고와 내부 장부 대조
  5. 주문 여부 확인 전 자동 재전송 금지
  6. 확인할 수 없으면(후보 여러 건, 조회 실패, 조회와 잔고 불일치) **해당 장부 거래 중단, 사람이 수동으로 확인하기 전까지 재개하지 않음**
- **재시작:** 항상 SAFE 모드로 시작 → 미완료 주문·잔고 대사 → 일치하면 정상 운영
- **대사:** 체결 직후·장 마감 후·시작 시·매주, 통화별로 따로. 외부 활동(직접 매매·환전)이나 설명할 수 없는 불일치는 장부 정지
- **API 오류:** 조회는 백오프로 재시도, 주문은 재시도하지 않음, 서킷 브레이커. 해외 IP 차단 응답으로 보이는 오류는 즉시 전체 정지 + 알림
- **시세 품질:** 신선도, 지연 플래그, 이상치, 교차 검증 → 해당 종목 또는 장부 차단
- **킬 스위치 [확정 C2]:** L1 Soft Halt(신규 매수 차단, 손절 매도만 허용 가능) / L2 Book Halt(장부 전체 주문 차단, 미체결 취소) / L3 Global Halt. **자동 전량 매도는 하지 않으며**, 청산은 사람이 명시적으로 명령하고 한 번 더 확인했을 때만 합니다

## 13. 운영 환경 및 보안 (요약)

상세: [기술 위험 검토 7장](docs/technical-risk-review.md), [KB API 조사 7장](docs/kb-openapi-research.md)

- **환경 분리:** 개발(Claude Cloud, 개인 PC)에는 비밀정보가 없습니다. **Claude Cloud 세션은 운영 서버로 쓰지 않습니다.**
- **네트워크 [확정: 국내 리전 고정 IP 우선 검토]:**
  - KB는 해외 IP 접속·API 호출을 차단합니다 [확인]. 해외 IP 차단과 IP 사전 등록(화이트리스트)은 별개이며, 사전 등록 제도는 공식 자료에 없습니다 [미확인].
  - AWS 서울 리전 IP를 KB가 국내로 판정하는지는 [미확인] → P3 전 **사전 접속 확인**(사용자가 운영 서버에서 토큰 발급 1회 + 조회 API 1회, 주문 API 호출 없음). 막히면 국내 클라우드 사업자로 전환
  - 고정 공인 IP는 공식 요구사항이 아니지만 권장 [제안]. 공인 IP 변경 감지 시 신규 주문 차단
  - `ipAddr`/`macAddr` 값은 설정으로 두고, KB 답변 후 기준 확정
  - VPN·해외 경유 금지
- **모의투자·실거래 격리 [확정 C7]:** 같은 인프라, 별도 프로세스·서비스·DB·인증정보. 모의투자 이미지에 KB 주문 모듈 없음
- **자동 복구:** 서비스 자동 재시작, 시작 시 SAFE 모드와 대사
- **백업:** 매일 암호화 DB 백업을 외부 저장소에 30일 보관, 매월 복구 리허설
- **비밀정보:** 암호화 파일 또는 Secret Manager, 로그 자동 마스킹, 키 교체·폐기 절차
- **접근 권한:** 서비스 계정과 관리자 분리, SSH 키 인증, 외부 포트 최소화, DB 계정 분리(모의투자/실거래, 읽기/쓰기)
- **알림·감시:** 텔레그램 3단계 알림, heartbeat와 외부 감시, `/status` `/halt` `/resume` 명령
- **운영 비용(추정):** 월 약 $13~18(최소) / $54~74(권장) / $183(확장)

## 15. 단계별 승인 기준 (게이트)

> **수익률 하나만으로 다음 단계에 가지 않습니다.** 모든 게이트는 수익 외에 위험, 비용, 운영 안정성 기준을 함께 봅니다. 기간을 채운 것만으로는 통과하지 않습니다. 수치는 모두 [제안] 초기값입니다.

### G1. 백테스트 통과 기준 (P1·P2 종료 시, **정량 전략에만 적용**)
- 비용 차감 후 walk-forward OOS Sharpe ≥ 0.8이고, 학습 구간 Sharpe의 70% 이상 유지
- OOS MDD ≤ 25%
- Profit Factor ≥ 1.2
- walk-forward 구간의 60% 이상에서 B0·B1보다 위험 대비 성과가 좋음
- 3가지 시장 상황(상승·하락·고변동) 중 어느 하나에서도 MDD가 한도를 넘지 않음
- 스트레스 시나리오(비용 2배, 참여율 절반, 체결 1봉 지연)에서도 초과수익이 0보다 큼
- 다중 검정 보정 Sharpe가 유의함
- 생존편향 경고가 없는 데이터로 계산한 결과일 것
- 잠금 테스트 구간 결과가 walk-forward 결과와 크게 다르지 않을 것
- **LLM 전략(B·C)의 과거 백테스트는 G1 판단 근거로 쓰지 않음**

### G2. AI 기여 기준 (P4 진행 중, 전향적 모의투자 결과로만 판단)
- C가 A보다 **AI 비용을 뺀 뒤에도** 위험 대비 성과가 좋고, 그 차이의 신뢰구간이 0을 넘을 것
- AI 판단 기록 누락률 0%(기록이 없는 판단은 매매에 쓰지 않았음을 확인)
- 충족하지 못하면 실거래는 A로 시작(λ=0)하는 것이 기본 권고

### G3. 모의투자 성과 기준 (P4 종료 시)
- 기간: **최소 3개월이면서** 각 시장 60거래일 이상, 리밸런싱 50회 이상
- v0.2 성공 기준 유지: 장부별 벤치마크 대비 초과수익(비용·AI 비용 차감 후), MDD ≤ 15%, Sharpe ≥ 1.0. 3개월 Sharpe는 통계적으로 불안정하므로 신뢰구간을 함께 보고하고, 하한이 0 이하이면 **조건부 통과**로 표시
- 같은 기간 백테스트 재현 결과와 모의투자 결과의 차이가 연환산 3%p 이내
- 거래 비용 비중(비용 / 총수익) ≤ 30%

### G4. 운영 안정성 기준 (P4 종료 시)
- **중복 주문 0건**(허용하지 않음)
- 리스크 한도 위반 주문 0건
- 하루를 넘겨 해결되지 않은 UNKNOWN 주문 0건
- 응답 유실 장애 주입 시험에서 6단계 규칙(10장)이 모두 동작하고, 확인 불가 상황에서 장부가 정지되며 수동 확인 전까지 재개되지 않음을 확인
- 시스템 버그로 생긴 주문 오류 주문 1,000건당 1건 이하, 원인 분석 완료
- **대사 성공률 ≥ 99%**, 설명할 수 없는 불일치 0건(발생하면 원인 해결 후 20거래일 연속 무결점부터 다시 측정)
- 장애 복구 시험 통과: 네트워크 단절, 주문 응답 유실, 프로세스 강제 종료, 서버 재부팅, 토큰 만료, 호출 제한 초과, 지연·이상 시세, AI 장애·비용 한도 초과, DB 복구 리허설, 공인 IP 변경 감지
- 킬 스위치 L1~L3 발동·해제 시험 통과(자동 청산이 일어나지 않음을 확인)
- 모의투자 서비스가 주문 API를 호출할 수 없음을 확인(이미지 검사, 허용 목록 시험)

### G5. 실거래 전환 승인 조건
- G1~G4 모두 통과(조건부 항목은 사용자가 명시적으로 수용)
- KB 확인 완료: 약관상 자동매매 가능 여부, 호출 제한, 주문 권한, 네트워크 조건(국내 IP 판정, 사전 등록 필요 여부, `ipAddr`/`macAddr` 기준), 통합증거금 해지 여부
- 자격증명 위험 명시: 모의투자 서비스가 주문 권한이 있는 키를 갖고 있는지 여부와 그 대응
- 사용자가 작성한 승인 파일(승인일, 장부별 실거래 한도, 최대 허용 손실액)
- 소액 한도로 시작, 최소 2주 반자동(주문별 사람 승인), 이후 자동 전환도 별도 승인
- 실거래 초기 페이퍼 병행 비교로 체결 모델 차이를 측정하고, 롤백 절차(실거래 → 페이퍼 즉시 전환) 시험 완료

## 18. 주요 리스크 (요약)

상세: [기술 위험 검토 1장](docs/technical-risk-review.md)

| 리스크 | 대응 |
|---|---|
| 사용자 지정 주문 ID 없음 → 브로커 멱등성 없음, 응답 유실 시 중복 주문 | 내부 통제로 위험을 줄이고 감지, 재전송 금지, 잔고 대조, 확인 불가 시 수동 확인 전까지 거래 중단 |
| **해외 IP 차단, 클라우드 IP 판정 불확실** | 국내 리전 고정 IP, 사전 접속 확인, 국내 클라우드 사업자 대안 |
| 페이퍼 체결이 실제와 다름, 과거 대기열 재현 불가 | 호가를 체결 보장으로 보지 않는 보수적 모델, 한계 문서화, 실거래 초기 병행 비교 |
| LLM 미래 정보 누수, 평가 기간 짧음 | LLM 백테스트는 참고용, 전향적 모의투자로 평가, λ 자동 하향 |
| 과최적화·생존편향 | walk-forward, 잠금 구간, 다중 검정 보정, 상장폐지 포함 데이터 |
| 장부 불일치·외부 활동 | 통화별 대사, 외부 활동 감지 시 정지, 자동매매 전용 단일 계좌 |
| 통화 혼용(통합증거금) | 통합증거금 사용 금지, Money 타입, 순수 외화 주문가능금액만 사용 |
| 모의투자 프로세스가 실주문을 낼 위험 | 별도 서비스·DB·인증정보, paper 이미지에 주문 모듈 없음, 허용 목록, 조회 전용 자격증명(가능 시) |
| API 장애·호출 제한·명세 변경 | 서킷 브레이커, 토큰버킷, 명세 해시 비교, 계약 테스트 |
| 데이터 공급자 중단 | Provider 인터페이스, 대체 공급자, 원본 저장 |
| AI 비용 폭증 | 일·월 한도, 캐싱, Batch, 정량 단독 fallback |
| 키 유출·개발 환경 오용 | 운영 서버에만 키, 로그 마스킹, Claude Cloud 개발 전용 |
| 개발 결과 유실(GitHub 푸시 불가) | P0 전 권한 해결 |
| 법·세금·약관 | 본인 계좌·자금만 운용, KB 약관 확인, 거래·세금 기록 보관 |
